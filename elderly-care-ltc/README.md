# ระบบดูแลผู้สูงอายุและผู้มีภาวะพึ่งพิง (LTC Dashboard)

Web App แบบครบวงจรสำหรับกองทุนดูแลระยะยาว (Long-Term Care) ของ อปท./รพ.สต.
ครอบคลุมงานตั้งแต่ทะเบียนประชากร ไปจนถึงการจ่ายค่าตอบแทนและการจัดทำโครงการ
**ฐานข้อมูล Supabase (PostgreSQL)** · **รันบน Google Apps Script Web App** · มีระบบล็อกอินแยกบทบาท

---

## 1. ภาพรวมการทำงาน (Workflow)

```
นำเข้า/บันทึกประชากร ─► สำรวจประชากร ─► ประเมิน ADL (Barthel 0-20)
                                              │  จัดระดับ ติดสังคม/ติดบ้าน/ติดเตียง
                                              │  จัดกลุ่มชุดสิทธิประโยชน์ 1-4 อัตโนมัติ
                                              ▼
                 Caregiver / Care Manager ─► จัดทำ Care Plan (ร่าง → อนุมัติ → ดำเนินการ → ปิด)
                                              │  ปรับแก้แผน = เก็บฉบับเดิม + เหตุผล (version)
                                              ▼
                           CG บันทึกการเยี่ยมตามแผน + สัญญาณชีพ + พิกัด + แนบรูป
                                              │  CM ตรวจสอบ (ผ่าน / ส่งกลับ)
                                              ▼
              คำนวณค่าตอบแทน CG และ CM รายเดือน ─► อนุมัติ ─► บันทึกจ่าย
                                              ▼
            จัดทำโครงการดูแลผู้สูงอายุ/ผู้พิการ (ดึงรายชื่อเป้าหมายอัตโนมัติ)
                                              ▼
                       รายงาน/ส่งออก Excel · Word · PDF
```

## 2. โมดูลในระบบ

| เมนู | ความสามารถ |
|---|---|
| **Dashboard** | KPI ประชากร/ผู้สูงอายุ/ผู้พิการ/ผู้เข้าเกณฑ์ LTC, กราฟระดับการพึ่งพิง, กลุ่ม 1-4, การเยี่ยมย้อนหลัง 12 เดือน, รายหมู่บ้าน, รายการที่ต้องดำเนินการ · CG เห็น Dashboard เฉพาะผู้รับบริการของตน |
| **ทะเบียนประชากร** | ค้นหา/กรอง (หมู่, 60+, ผู้พิการ, สถานะ), เพิ่ม/แก้ไข, **นำเข้า Excel/CSV** (จับคู่หัวคอลัมน์ไทย/อังกฤษอัตโนมัติ, รองรับวันที่ พ.ศ./ค.ศ., เลขบัตรซ้ำ = อัปเดต, มีไฟล์ต้นแบบ), หน้ารายละเอียดรายบุคคลรวมทุกประวัติ |
| **สำรวจประชากร** | การอยู่อาศัย ผู้ดูแลหลัก รายได้ สภาพบ้าน อุปกรณ์ ความต้องการช่วยเหลือ → ต่อไปประเมิน ADL ได้ทันที |
| **ประเมิน ADL** | แบบประเมิน Barthel 10 ข้อ คำนวณคะแนนสด, ระดับการพึ่งพิง, กลุ่มชุดสิทธิประโยชน์ (ภาวะสับสน/ระยะท้าย) · เกณฑ์ปรับได้ในตั้งค่า · เข้าเกณฑ์แล้วเสนอให้จัดทำ Care Plan ต่อ |
| **Care Plan** | ดึงผล ADL ล่าสุด, เลือก CM/CG, ปัญหา/เป้าหมาย, กิจกรรมตามชุดสิทธิประโยชน์ (มีชุดมาตรฐานตามกลุ่ม), คำนวณงบต่อเดือน/ตลอดแผน เทียบเพดานกลุ่ม, ขั้นตอนอนุมัติ, **การปรับแก้แผนเก็บประวัติทุกฉบับพร้อมเหตุผล**, ส่งออกเอกสาร Care Plan (Word/PDF) พร้อมช่องลงนาม |
| **การปฏิบัติงาน CG** | CG เลือกผู้รับบริการ → เช็กลิสต์กิจกรรมตามแผน, เวลา, สัญญาณชีพ (BP, ชีพจร, T, DTX, น้ำหนัก), บันทึก/ปัญหา, พิกัด GPS, **แนบรูปได้ 10 รูป** (ย่อขนาดอัตโนมัติ เก็บใน Supabase Storage แบบ private) · CM ตรวจผ่าน/ส่งกลับ ทีละรายการหรือหลายรายการ · ส่งออกบันทึกพร้อมรูปเป็น Word/PDF |
| **CG / CM** | ทะเบียน Caregiver (ชั่วโมงอบรม, ใบรับรอง, CM ผู้กำกับ, บัญชีธนาคาร, จำนวนเคส) และ Care Manager |
| **ค่าตอบแทน CG** | คำนวณจากการเยี่ยมที่ตรวจแล้ว: คิดรายครั้ง หรือรายผู้รับบริการ/เดือน + เพดาน · อนุมัติ → จ่ายแล้ว · รายการที่อนุมัติแล้วไม่ถูกคำนวณทับ |
| **ค่าตอบแทน CM** | จำนวนเคสที่ดูแลในงวด × อัตรา + แผนใหม่ที่อนุมัติในงวด × อัตรา + เพดาน |
| **โครงการ** | แบบฟอร์มโครงการมาตรฐานราชการ (หลักการและเหตุผล, วัตถุประสงค์, เป้าหมาย, ระยะเวลา, กิจกรรม/งบ, ผลที่คาดว่าจะได้รับ, การประเมินผล), **ร่างข้อความอัตโนมัติจากสถิติจริง**, ดึงรายชื่อผู้เข้าเกณฑ์ LTC เป็นภาคผนวก, งบประมาณเป็นตัวอักษรไทย, ส่งออก Word/PDF |
| **รายงาน/ส่งออก** | 9 รายงาน × 3 รูปแบบ (Excel / Word / PDF) — บัญชีค่าตอบแทนมีช่องลายมือชื่อผู้รับเงินและผู้อนุมัติ |
| **ตั้งค่า** | ข้อมูลหน่วยงาน, อัตราค่าตอบแทน/เพดานงบตามกลุ่ม, เกณฑ์ ADL, จัดการผู้ใช้, บันทึกการใช้งาน (audit log), เปลี่ยนรหัสผ่าน |

## 3. บทบาทผู้ใช้ (สิทธิ์)

| บทบาท | สิทธิ์ |
|---|---|
| `admin` ผู้ดูแลระบบ | ทุกเมนู, ตั้งค่า, ผู้ใช้, ลบข้อมูล, อนุมัติค่าตอบแทน CM |
| `cm` Care Manager | จัดการประชากร/สำรวจ/ADL/CG/Care Plan, อนุมัติแผน, ตรวจการเยี่ยม, คำนวณ/อนุมัติค่าตอบแทน CG |
| `cg` Caregiver | เห็นเฉพาะผู้รับบริการที่ได้รับมอบหมาย, บันทึก/แก้ไขการเยี่ยมของตน (ก่อนตรวจ), ดูค่าตอบแทนของตน |
| `viewer` ผู้บริหาร | ดู Dashboard / ข้อมูล / รายงาน (อ่านอย่างเดียว) |

สิทธิ์ตรวจที่ฝั่ง server ทุกคำสั่ง (ดู `ACTIONS` ใน `gas/Services.gs`) ไม่ได้พึ่งการซ่อนปุ่มฝั่งหน้าเว็บ

## 4. สถาปัตยกรรม

```
 เบราว์เซอร์ / มือถือ (HtmlService SPA)
   │  google.script.run.api(token, action, payload)
   ▼
 Google Apps Script (Code.gs / Services.gs / Export.gs)
   │  ตรวจ session + สิทธิ์ตามบทบาท
   │  UrlFetchApp + service_role key (เก็บใน Script Properties)
   ▼
 Supabase ─ PostgREST (ตาราง/วิว/RPC dashboard_summary)
          └ Storage bucket "visit-photos" (private, signed URL 1 ชม.)
 Google Docs (ไฟล์ชั่วคราว) ─► export .docx / .pdf ─► ลบทิ้งอัตโนมัติ
```

- **ความปลอดภัย**: ทุกตารางเปิด RLS โดยไม่มี policy → anon key เข้าถึงไม่ได้; key ของ Supabase อยู่ฝั่ง server เท่านั้น
- **ล็อกอิน**: ตาราง `app_users` เก็บรหัสผ่านแบบ salted SHA-256 (500 รอบ), session token อยู่ใน CacheService 6 ชม. (ต่ออายุเมื่อใช้งาน), ล็อก 15 นาทีเมื่อผิด 5 ครั้ง
- **Excel** สร้างฝั่งเบราว์เซอร์ด้วย SheetJS · **Word/PDF** สร้างผ่าน Google Docs ฟอนต์ Sarabun

### โครงสร้างไฟล์

```
elderly-care-ltc/
├── supabase/schema.sql      ตาราง, view, RPC, ค่าตั้งต้น, storage bucket, RLS
├── gas/
│   ├── appsscript.json      manifest (scopes, webapp)
│   ├── Code.gs              doGet, login/logout, API dispatcher, audit
│   ├── Supabase.gs          REST client (select/insert/upsert/update/delete/rpc/storage)
│   ├── Services.gs          business logic ทุกโมดูล + ทะเบียนสิทธิ์ ACTIONS
│   ├── Export.gs            รายงาน + สร้างเอกสาร Word/PDF (Care Plan, การเยี่ยม, โครงการ, บัญชีจ่ายเงิน)
│   ├── Index.html           โครงหน้าเว็บ + หน้าล็อกอิน
│   ├── Styles.html          CSS (รองรับมือถือ)
│   └── App.html             JavaScript ฝั่งหน้าเว็บทั้งหมด
└── docs/data-model.md       แผนภาพฐานข้อมูล
```

## 5. วิธีติดตั้ง

### 5.1 Supabase
1. สร้างโปรเจกต์ที่ <https://supabase.com>
2. เปิด **SQL Editor** → วางเนื้อหา `supabase/schema.sql` → Run
3. ไปที่ **Project Settings → API** จด `Project URL` และ `service_role` key (ห้ามเผยแพร่ key นี้)

### 5.2 Google Apps Script
1. ไปที่ <https://script.google.com> → New project
2. Project Settings → ติ๊ก *Show "appsscript.json" manifest file*
3. สร้างไฟล์ให้ตรงกับโฟลเดอร์ `gas/` (ไฟล์ `.gs` = Script, ไฟล์ `.html` = HTML ชื่อไม่ต้องมีนามสกุล เช่น `Index`, `Styles`, `App`) แล้วคัดลอกเนื้อหา
   - หรือใช้ [clasp](https://github.com/google/clasp): `clasp create --type webapp --rootDir gas` แล้ว `clasp push`
4. Project Settings → **Script Properties** เพิ่ม
   | Property | ค่า |
   |---|---|
   | `SUPABASE_URL` | `https://xxxx.supabase.co` |
   | `SUPABASE_SERVICE_KEY` | service_role key |
   | `ADMIN_INITIAL_PASSWORD` | รหัสผ่านเริ่มต้นของ admin (≥ 8 ตัว) |
5. เลือกฟังก์ชัน `createInitialAdmin` → Run (อนุญาตสิทธิ์) → **ลบ** `ADMIN_INITIAL_PASSWORD` ออกหลังรันสำเร็จ
6. Deploy → New deployment → Web app → *Execute as: Me* · *Who has access: Anyone* → ได้ URL ใช้งาน
7. เข้าระบบด้วย `admin` → ไปที่ **ตั้งค่า** กรอกข้อมูลหน่วยงาน อัตราค่าตอบแทน แล้วสร้างผู้ใช้ CM / CG

> หลังแก้โค้ดต้อง Deploy → Manage deployments → Edit → New version จึงจะมีผลกับ URL เดิม

### 5.3 การนำเข้าข้อมูลประชากรครั้งแรก
เมนู **ทะเบียนประชากร → นำเข้า Excel/CSV** → ดาวน์โหลดไฟล์ต้นแบบ หรือใช้ไฟล์จาก JHCIS/HosXP/ทะเบียนราษฎร์
ที่มีหัวคอลัมน์ เช่น `เลขบัตรประชาชน, คำนำหน้า, ชื่อ, นามสกุล, เพศ, วันเกิด, บ้านเลขที่, หมู่` (หรือ `ชื่อ-สกุล` คอลัมน์เดียว) นำเข้าครั้งละไม่เกิน 5,000 แถว/ไฟล์ส่งเป็นชุดละ 1,000

## 6. ค่าที่ต้องตรวจสอบก่อนใช้งานจริง

ค่าตั้งต้นในระบบเป็น **ตัวอย่าง** ปรับได้ที่เมนูตั้งค่า กรุณาตรวจให้ตรงกับประกาศ สปสช. และประกาศคณะอนุกรรมการกองทุน LTC ของพื้นที่:
- งบต่อผู้มีภาวะพึ่งพิง/ปี และเพดาน Care Plan ของแต่ละกลุ่ม (ตั้งต้น 10,442 บาท)
- อัตราค่าตอบแทน CG (ต่อครั้ง/ต่อคน) และ CM, เพดานต่อเดือน
- เกณฑ์ ADL (ติดเตียง ≤ 4, ติดบ้าน ≤ 11, เข้าเกณฑ์ LTC ≤ 11)
- หลักการจัดกลุ่ม 1-4 ที่ใช้: ระยะท้าย → กลุ่ม 4, ADL ≤ 4 → กลุ่ม 3, มีภาวะสับสน → กลุ่ม 2, อื่นๆ → กลุ่ม 1 (แก้ได้ที่ `calcAdl_` ใน `Services.gs` และ `calcAdl` ใน `App.html`)

## 7. ข้อจำกัดของ Google Apps Script ที่ควรทราบ
- เวลาประมวลผลต่อคำสั่งสูงสุด 6 นาที, UrlFetch ~20,000 ครั้ง/วัน (บัญชีทั่วไป) — เพียงพอสำหรับระดับตำบล
- รายงาน Word/PDF ใช้เวลาประมาณ 5-15 วินาที (สร้างผ่าน Google Docs)
- ส่งออกรายงานแบบตารางสูงสุด 500-1,000 แถวต่อไฟล์ (กรองตามหมู่/ช่วงเวลาได้)
- รูปภาพ: ย่อเหลือด้านยาวไม่เกิน 1,600px ก่อนอัปโหลด, สูงสุด 4MB/รูป, 10 รูป/การเยี่ยม

## 8. แก้ปัญหาที่พบบ่อย

| อาการ | สาเหตุ / วิธีแก้ |
|---|---|
| กดเข้าสู่ระบบแล้วหน้าขาว | ใช้เวอร์ชันเก่าของ `App.html`/`Index.html` — คัดลอกไฟล์ล่าสุดแล้ว **Deploy → Manage deployments → Edit → Version: New version** (ถ้าไม่สร้างเวอร์ชันใหม่ URL เดิมจะยังใช้โค้ดเก่า) |
| มีข้อความแดง "เริ่มระบบไม่สำเร็จ: Supabase 401/404 ..." | ตรวจ `SUPABASE_URL` (ไม่มี `/` ท้าย) และ `SUPABASE_SERVICE_KEY` ต้องเป็น **service_role** ไม่ใช่ anon key และต้องรัน `schema.sql` แล้ว |
| "ชื่อผู้ใช้หรือรหัสผ่านไม่ถูกต้อง" ทั้งที่เพิ่งตั้ง | ยังไม่ได้รัน `createInitialAdmin` หรือรันก่อนตั้ง `ADMIN_INITIAL_PASSWORD` — ตั้งค่าแล้วรันใหม่ (ชื่อผู้ใช้คือ `admin`) |
| "โหลดสคริปต์ของระบบไม่สำเร็จ" | กด F12 → Console ดูข้อความ error แล้วแจ้งผู้พัฒนา |

# คู่มือปฏิบัติงานประจำ

สำหรับเจ้าหน้าที่งานบุคคลและผู้ดูแลระบบ — งานที่ต้องทำตามรอบเวลา
และวิธีรับมือกับสถานการณ์ที่พบบ่อย

---

## 1. ปฏิทินงานประจำ

### รายวัน (ระบบทำเอง)

| เวลา | งาน | ต้องตรวจอะไร |
|---|---|---|
| 01:00 | คำนวณสรุปเวลาของเมื่อวาน | ดู Executions ว่า `jobNightlyAttendance` สำเร็จ |
| 07:00 | ส่งเตือนรายการใกล้ครบกำหนด | — |
| ทุก 15 นาที | ส่งอีเมล/LINE จากคิวแจ้งเตือน | หากมี `notifications.status = 'FAILED'` ให้ดู `error_message` |

**งานที่คนต้องทำ**
- ตรวจใบลาที่รออนุมัติ (โมดูล 06 → แท็บ *รออนุมัติ*)
- ตรวจคำขอแก้ไขเวลา (โมดูล 05 → แท็บ *คำขอแก้ไขเวลา*)
- ออกเอกสารตามคำขอ (โมดูล 12)

### รายเดือน

| ช่วง | งาน | หน้าจอ |
|---|---|---|
| ต้นเดือน | สร้างงวดการจ่ายของเดือน | 07 เงินเดือน → *งวดการจ่าย* |
| ก่อนวันตัดยอด | ตรวจว่าใบลา/ล่วงเวลาของเดือนอนุมัติครบแล้ว | 05, 06 |
| หลังวันตัดยอด | สร้างรอบ → ประมวลผล → ตรวจ → อนุมัติ → บันทึกจ่าย | 07 เงินเดือน → *รอบประมวลผล* |
| วันจ่าย | สร้างไฟล์นำเข้าธนาคาร | 07 → ปุ่ม *ไฟล์ธนาคาร* |
| สิ้นเดือน | ตรวจสรุปการมาปฏิบัติงาน | 05 → *สรุปรายเดือน* |

### รายปี (ปีงบประมาณ 1 ต.ค. – 30 ก.ย.)

| ช่วง | งาน |
|---|---|
| ก.ย. | ตรวจรายชื่อผู้ครบเกษียณ (โมดูล 14 → *ผู้ครบเกษียณ*) และเตรียมคำสั่ง |
| ก.ย. | บันทึกวันหยุดราชการของปีถัดไป (โมดูล 05 → ตั้งค่า) |
| 1 ต.ค. | ระบบตั้งสิทธิวันลาปีใหม่ + ยกยอดลาพักผ่อนอัตโนมัติ — **ตรวจผลด้วย** |
| ต.ค. | กำหนดกรอบอัตรากำลังปีใหม่ (โมดูล 02 → *กรอบอัตรากำลัง*) |
| ต.ค. | เปิดรอบประเมินรอบที่ 1 (โมดูล 09) |
| มี.ค.–เม.ย. | ปิดรอบประเมินรอบที่ 1 → เสนอเลื่อนเงินเดือน |
| ก.ย.–ต.ค. | ปิดรอบประเมินรอบที่ 2 → เสนอเลื่อนเงินเดือน |

> **ตรวจการยกยอดวันลา** หลังวันที่ 1 ต.ค.
> ```sql
> select period_year, count(*), sum(carried_over_days)
>   from leave_entitlements
>  where leave_type_id = (select id from leave_types where code='VACATION')
>  group by 1 order by 1 desc limit 3;
> ```

## 2. กระบวนงานทีละขั้น

### 2.1 รับบุคลากรใหม่

```
1. โมดูล 04 → สร้างประกาศรับสมัคร → ตั้งสถานะ "เปิดรับสมัคร"
   (ติ๊ก "เผยแพร่สาธารณะ" หากต้องการเปิดหน้าเว็บสมัครออนไลน์)
2. ผู้สมัครยื่นผ่าน <WebAppURL>?page=jobs  หรือเจ้าหน้าที่คีย์ให้
3. โมดูล 04 → แท็บผู้สมัคร → บันทึกคะแนน → เปลี่ยนขั้นตอนเป็น "ผ่านการคัดเลือก"
4. กดปุ่ม "บรรจุ" → กรอกรหัสบุคลากร วันเริ่มงาน ตำแหน่ง เงินเดือน
   ระบบจะสร้างทะเบียนประวัติ โอนประวัติการศึกษา/ประสบการณ์
   สร้างการดำรงตำแหน่งแรก ตั้งรายการเตรียมความพร้อม 8 รายการ
   และตั้งสิทธิวันลาให้อัตโนมัติ
5. โมดูล 04 → แท็บบุคลากรใหม่ → ทยอยติ๊กรายการที่ทำเสร็จ
6. ผู้ใช้และสิทธิ → สร้างบัญชีจากทะเบียนบุคลากร
7. โมดูล 03 → เพิ่มกะการทำงานและผู้บังคับบัญชา (จำเป็นสำหรับสายอนุมัติลา)
```

### 2.2 ประมวลผลเงินเดือน

```
1. ตรวจว่าใบลาและล่วงเวลาของงวดอนุมัติครบแล้ว
2. โมดูล 07 → งวดการจ่าย → สร้างงวด (ถ้ายังไม่มี)
3. รอบประมวลผล → + สร้างรอบใหม่
4. กด "ประมวลผล" → ระบบคำนวณให้ทุกคน
5. ตรวจผล: กด "สลิป" ดูรายการ สุ่มตรวจ 3–5 คน
6. กด "อนุมัติ" (หลังอนุมัติแก้ไขไม่ได้)
7. กด "ไฟล์ธนาคาร" → ได้ CSV สำหรับนำเข้าระบบธนาคาร
8. หลังโอนเงินสำเร็จ → กด "บันทึกจ่าย"
```

**หากประมวลผลแล้วตัวเลขไม่ถูก**

| อาการ | ตรวจที่ไหน |
|---|---|
| เงินเดือนเป็น 0 | `employment_assignments.base_salary` ของคนนั้น หรือรายการ `BASE` ใน `employee_pay_components` |
| หักขาดงานเกินจริง | `attendance_daily` ของงวดนั้น — อาจยังไม่ได้คำนวณสรุปเวลา |
| ไม่มีค่าล่วงเวลา | ใบขอล่วงเวลาต้องสถานะ `APPROVED` และอยู่ในช่วงงวด |
| ประกันสังคมผิด | `contribution_rates` — ตรวจ `effective_from` และเพดาน |
| ภาษีสูงผิดปกติ | ระบบประมาณการรายปีจากเงินได้เดือนนั้น × 12 — เดือนที่มีโบนัสจะสูงกว่าปกติ |

> ประมวลผลซ้ำได้ตลอดจนกว่าจะกดอนุมัติ ระบบลบสลิปเดิมของรอบแล้วสร้างใหม่

### 2.3 เลื่อนตำแหน่ง/ย้ายหน่วยงาน

```
1. โมดูล 11 → + ร่างคำสั่ง → เลือกบุคลากร ประเภท วันที่มีผล และค่าใหม่
   (ระบบดึงค่าปัจจุบันมาเป็นค่าเดิมให้อัตโนมัติ)
2. กด "อนุมัติ"
3. กด "ดำเนินการ" → ระบบปิดการดำรงตำแหน่งเดิมที่วันก่อนหน้าวันมีผล
   เปิดแถวใหม่ บันทึก timeline และประวัติเงินเดือน
```

> ขั้นที่ 3 ย้อนกลับไม่ได้ผ่านหน้าจอ หากผิดพลาดต้องแก้ที่ฐานข้อมูล
> ตรวจวันที่มีผลและค่าใหม่ให้ถูกต้องก่อนกด

### 2.4 บุคลากรลาออก/เกษียณ

```
1. โมดูล 14 → + ยื่นคำขอ (บุคลากรยื่นเองได้ผ่าน self-service)
   ระบบสร้างรายการเคลียร์ของ 8 รายการอัตโนมัติ
2. ผู้บังคับบัญชากด "อนุมัติ"
3. หน่วยงานที่เกี่ยวข้องทยอยติ๊กรายการเคลียร์
4. เมื่อเคลียร์ครบ → กด "ดำเนินการพ้นสภาพ"
   ระบบปิดการดำรงตำแหน่ง ปรับสถานะ ระงับบัญชีผู้ใช้ ปิดสิทธิสวัสดิการ
5. สัมภาษณ์ก่อนลาออก (ถ้ามีนโยบาย) — บันทึกไว้ใช้วิเคราะห์ turnover
```

> ระบบไม่ยอมให้กดขั้นที่ 4 หากยังมีรายการค้างเคลียร์ — บังคับที่ฐานข้อมูล
> ข้อมูลของผู้พ้นสภาพยังอยู่ครบ เพียงไม่ปรากฏในรายการที่กรองสถานะปฏิบัติงาน

### 2.5 รอบประเมินผล

```
1. โมดูล 09 → รอบการประเมิน → + สร้างรอบ
2. กด "เปิดรอบ" → เลือกแบบประเมิน
   ระบบสร้างใบประเมินให้ทุกคน พร้อมกำหนดผู้ประเมินจากผู้บังคับบัญชา
3. บุคลากรประเมินตนเอง (แท็บ "การประเมินของฉัน")
4. ผู้บังคับบัญชาประเมิน (แท็บ "ประเมินผู้ใต้บังคับบัญชา")
5. ผู้มีอำนาจกด "อนุมัติผลประเมิน"
6. บุคลากรกด "รับทราบผล"
7. เสนอเลื่อนเงินเดือน → ตรวจ → นำไปใช้จริง
```

## 3. งานดูแลระบบ

### 3.1 เพิ่มสิทธิให้ผู้ใช้

```
ผู้ใช้และสิทธิ → หาผู้ใช้ → กำหนดสิทธิ → เลือกบทบาท
  · เว้นช่อง "จำกัดเฉพาะสถานบริการ" = มีสิทธิทั้งองค์กร
  · ระบุสถานบริการ = เห็นเฉพาะบุคลากรในสถานบริการนั้น
  · ใส่ "สิ้นสุดสิทธิวันที่" สำหรับสิทธิชั่วคราว เช่นช่วงรักษาการ
```

หลังแก้สิทธิ ผู้ใช้ต้องกดปุ่ม **รีเฟรช** บนหัวเว็บ (แคชสิทธิเก็บไว้ 5 นาที)

### 3.2 ตรวจสอบเมื่อมีข้อสงสัยเรื่องข้อมูล

```
โมดูล Audit Log → การเปลี่ยนแปลงข้อมูล → กด "ดู"
  เห็นค่าเดิม/ค่าใหม่ทีละฟิลด์ พร้อมชื่อผู้แก้และเวลา
```

หรือดูเฉพาะระเบียนหนึ่ง: โมดูล 03 → เปิดประวัติบุคลากร → แท็บเหตุการณ์
→ ปุ่ม *ประวัติการแก้ไขข้อมูล*

ตรวจว่าใครเปิดดูข้อมูลใครบ้าง: Audit Log → *การเข้าถึงข้อมูลส่วนบุคคล*

### 3.3 สำรองและกู้คืนข้อมูล

Supabase มีสำรองอัตโนมัติรายวัน (Settings → Database → Backups)

สำรองเพิ่มเองเป็นไฟล์:
```bash
pg_dump "$DB_URL" --no-owner --no-acl -Fc -f hrm_backup_$(date +%Y%m%d).dump
```

กู้คืนลงฐานข้อมูลใหม่:
```bash
pg_restore -d "$NEW_DB_URL" --no-owner --no-acl hrm_backup_20260824.dump
```

> ทดสอบกู้คืนอย่างน้อยปีละครั้ง — ไฟล์สำรองที่กู้ไม่ได้ไม่มีค่า

### 3.4 ติดตามโควตา Apps Script

| โควตา | ขีดจำกัด/วัน | ใช้ที่ไหน |
|---|---|---|
| `UrlFetchApp` | 20,000 ครั้ง | ทุกการเรียกฐานข้อมูล |
| `MailApp.sendEmail` | 1,500 ฉบับ (Workspace) | แจ้งเตือนทางอีเมล |
| เวลาทำงานสคริปต์ | 6 นาที/ครั้ง | ประมวลผลเงินเดือน, คำนวณเวลาย้อนหลัง |

หากชนโควตา `UrlFetchApp` ให้ลดความถี่ของ `jobSendNotifications`
จากทุก 15 นาทีเป็นทุก 30 นาที

## 4. สถานการณ์ที่พบบ่อย

### บุคลากรลืมบันทึกเวลาเข้า

```
บุคลากร: โมดูล 05 → ปุ่ม "แจ้งขอแก้ไขเวลา" → เลือกประเภท "เพิ่มเวลาเข้า"
หัวหน้า:  โมดูล 05 → แท็บคำขอแก้ไขเวลา → อนุมัติ
          ระบบเพิ่มบันทึกเวลาและคำนวณสรุปวันนั้นใหม่ให้อัตโนมัติ
```

### ลงเวลาแล้วขึ้น "นอกพื้นที่"

ตรวจพิกัดสถานบริการ:
```sql
select code, name_th, geo from facilities where org_id = '...';
```
แก้ให้ตรงกับพิกัดจริงและเพิ่มรัศมี:
```sql
update facilities
   set geo = jsonb_build_object('lat',13.7563,'lng',100.5018,'radius_m',500)
 where code = '10999';
```

การลงเวลานอกพื้นที่ยังบันทึกได้ เพียงติดธง `is_outside_geo` ไว้ให้ตรวจสอบ

### ต้องแก้ข้อมูลย้อนหลังแล้วตัวเลขรายงานไม่ตรง

```
โมดูล 05 → สรุปรายวัน → เลือกช่วงวันที่ → ปุ่ม "คำนวณใหม่"
(คำนวณได้ครั้งละไม่เกิน 62 วัน)
```

### ใบลาส่งไม่ได้ — "วันลาคงเหลือไม่พอ"

ตรวจสิทธิของคนนั้น:
```sql
select leave_type_code, total_days, used_days, pending_days, remaining_days
  from v_leave_balance where emp_code = 'EMP0001';
```
หากสิทธิยังไม่ถูกตั้ง: โมดูล 06 → ตั้งค่า → *ตั้งสิทธิวันลาประจำปี*
หากต้องปรับเฉพาะราย: ใช้ API `leave.entitlementAdjust` หรือแก้ผ่าน SQL
ที่คอลัมน์ `adjusted_days`

### บุคลากรไม่ปรากฏในรายการ

สาเหตุที่พบบ่อยที่สุดคือไม่มีการดำรงตำแหน่งที่ยังไม่ปิด:
```sql
select e.emp_code, e.employment_status,
       (select count(*) from employment_assignments a
         where a.employee_id = e.id and a.effective_to is null) as active_assignments
  from employees e
 where e.org_id = '...' and e.employment_status = 'ACTIVE';
```
แถวที่ `active_assignments = 0` ต้องสร้าง assignment ให้

### ประมวลผลเงินเดือนแล้วขึ้น "Exceeded maximum execution time"

แบ่งรอบตามสถานบริการ — สร้างหลายรอบในงวดเดียวกัน แต่ละรอบระบุ
`facility_id` ต่างกัน แล้วประมวลผลทีละรอบ

## 5. คำถามที่ถูกถามบ่อย

**ย้อนดูได้ไหมว่าเมื่อปีที่แล้วหน่วยงานนี้มีกี่คน**
ได้ เพราะ `employment_assignments` เก็บทุกช่วงเวลา:
```sql
select d.name_th, count(*)
  from employment_assignments a
  join departments d on d.id = a.department_id
 where a.effective_from <= '2568-09-30'
   and (a.effective_to is null or a.effective_to >= '2568-09-30')
   and a.assignment_type = 'PRIMARY'
 group by 1;
```

**เปลี่ยนสูตรคำนวณเงินเดือนได้ที่ไหน**
`calculatePayslip()` ใน `15_Api_Payroll.gs` — แก้แล้ว `clasp push` ได้ทันที
ไม่ต้องแตะฐานข้อมูล

**เพิ่มประเภทการลาใหม่ได้ไหม**
ได้ โมดูล 06 → ตั้งค่า → เพิ่มประเภทการลา ไม่ต้องแก้โค้ด

**ระบบรองรับกี่คน**
ข้อจำกัดหลักคือ 6 นาทีต่อการทำงานหนึ่งครั้งของ Apps Script
การประมวลผลเงินเดือนรองรับได้ประมาณ 300–500 คนต่อรอบ
เกินกว่านั้นให้แบ่งรอบตามสถานบริการ ส่วนงานอื่นไม่มีข้อจำกัดในทางปฏิบัติ

**เปิดให้บุคลากรใช้ผ่านมือถือได้ไหม**
ได้ หน้าเว็บรองรับจอมือถืออยู่แล้ว เปิด URL เดียวกันได้เลย
หากต้องการแอปเต็มรูปแบบ ดูหัวข้อ "เส้นทางต่อยอด" ใน `ARCHITECTURE.md`
